What are we doing?

  • PromoTrack is a client-side web application that enables employees to build, manage, and export their promotion portfolio in a single unified tool. It replaces the manual process of assembling STARR entries, performance metrics, and narrative sections across disconnected documents and spreadsheets.
  • The app runs entirely in the browser with AES-256-GCM encrypted local storage — no backend infrastructure required — and includes optional AI-assisted writing via local Ollama or Amazon Bedrock.
  • All portfolio data can be exported as encrypted portable files or formatted DOCX/PDF documents ready for submission.

Stakeholders / Customers:

  • Individual contributors preparing promotion portfolios (primary users)
  • Managers reviewing and approving promotion documents
  • STEAM committee members evaluating promotion readiness
  • IT Support / Engineering teams (initial rollout)

Why are we doing it?

  • Business justification: The current promotion process is fragmented — employees manually compile data from GSD scorecards and blank Word templates, leading to inconsistent quality and missed evidence. Employees spend significant time on formatting rather than content quality.
  • Impact in current state: No single tool tracks promotion readiness or identifies gaps in Leadership Principle coverage. Managers lack visibility into portfolio completeness before submission deadlines.
  • Related goals: Reduce portfolio preparation time from days to hours. Improve the quality and completeness of promotion submissions across the organization.

How are we doing it?

Components:

  • Lock Screen — passphrase-based access control with encrypted storage
  • Dashboard — readiness score (0–100), LP coverage chart, gap checklist
  • STARR Editor — create/edit entries with LP tagging and AI-assisted rewriting
  • Metrics Importer — parse GSD scorecard PDFs and CSV files
  • Documents Hub — export encrypted .portfolio files, DOCX, PDF, HTML
  • Profile — employee info, promotion targets, narrative sections
  • Timeline — chronological view of all portfolio activity
  • AI Assistant — gap analysis, scope drafting, STARR improvement

Technologies:

  • React 19, TypeScript, Vite 8, MUI 7, Recharts
  • Web Crypto API (AES-256-GCM, PBKDF2) for encryption
  • docx / jsPDF for document generation, DOMPurify for XSS prevention
  • Ollama (local AI) / Amazon Bedrock (cloud AI) — optional

Data stores:

  • Browser localStorage (AES-256-GCM encrypted) — sole data store, no backend database

External tech dependencies:

  • AWS Amplify Hosting (static SPA deployment with security headers)
  • Ollama / Amazon Bedrock (optional, for AI features)

Personnel:

  • 1 developer (design + implementation)
  • Manager review for requirements alignment
  • Security review for encryption and data handling

Backfills / modification of existing data:

  • None — greenfield application, no existing systems modified

Open questions:

  • Should we add Amazon Cognito authentication for multi-user / cross-device support in a future phase?
  • Is DynamoDB-backed persistence needed, or is client-only storage sufficient for the target audience?
  • Should the DOCX export format be standardized across the organization?
  • What is the appetite for a manager-facing read-only view of employee portfolios?

Summary of design review

  • Architecture: Client-side SPA with encrypted localStorage — no backend required, zero infrastructure cost
  • Security: AES-256-GCM encryption at rest and for exported files, passphrase lock screen on every load, AI endpoint allowlist, CSP headers, DOMPurify sanitization, file import validation — overall risk rating: LOW
  • Trade-off accepted: Client-only storage limits cross-device sync but eliminates backend complexity, cost, and data privacy concerns
  • AI: Optional and defaults to local-only (Ollama) to keep sensitive data off external servers
